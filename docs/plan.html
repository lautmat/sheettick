SheetTick Build Plan
Project plan · 19 Oct 2026

SheetTick: your own TickTick, stored in your Google Sheet

A Windows and Android task app with TickTick's feature set, where every task, list, habit and focus session lives as a readable row in a spreadsheet you own. This page covers what TickTick actually contains (from a REA reverse-engineering pass on the Windows app plus the official docs), whether something like this already exists, and how to build it.

Already exists?No

Nothing combines TickTick-level features, native Windows + Android apps and Google Sheets storage. The closest open-source apps miss at least two of the three.

Recommended stackFlutter + SQLite + Sheets API

One codebase for both apps. Local-first database on each device, synced to the Sheet. No server to run.

Effort~12 weeks, 4 phases

Usable daily driver after phase 1 (~5 weeks). Estimate assumes one developer working part-time with Claude Code.

REA investigation · TickTick for Windows

What's inside the Windows app

I ran REA (rea-agents 6.7.0) on your installed TickTick.exe, using inspect-managed-artifact for identity and metadata, then inspect-managed-members --type … on chosen types, because the whole assembly is over REA's 64 MB decode budget. The installed build is 4.0.8.0 from December 2021: a .NET Framework 4.5.2 WPF app for x64. The current release line is 8.x, so features added after 2021 (Countdown, Timeline, AI) were mapped from TickTick's official docs instead.

Size of the app

  • 6,295 types, 32,922 methods
  • 187 compiled XAML screens and dialogs
  • 52 DAO classes (local SQLite tables)
  • 122 API endpoints in 25 groups
  • 17 themes (Tokyo, London, Spring…), 5 UI languages

Feature modules (types per area)

  • Calendar 41 · Habit 30 · Config 28
  • Time / date pickers 22 · Pomodoro 17 · Search 17
  • Task list 22 · Tag 15 · Widget 14 · Print 14
  • Markdown editor 14 · Filter 13 · Detail 13
  • Quick add 11 · Kanban 10 · Lock 4 · Eisenhower 3

How TickTick syncs

  • Every device works on a local SQLite copy
  • Each row carries etag and syncStatus (dirty flag)
  • SyncService: commit dirty rows in batches (/api/v2/batch/task, …/project, …/tag…), then pull changes since a saved checkpoint
  • A WebSocket (wss://wss.ticktick.com/pc) only signals "need sync"

Libraries, and what SheetTick uses instead

  • Ical.Net (RRULE recurrence) → rrule (Dart)
  • SmartDateDLL (natural-language dates) → custom parser
  • CommonMark + AvalonEdit (Markdown notes) → flutter_markdown / editor
  • NHotkey (global quick-add hotkey) → hotkey_manager
  • KotlinMultiplatformAll.dll: TickTick shares business logic with Android through Kotlin Multiplatform

The data model below comes straight from REA's field listing of TickTick's model classes, including TaskModel (54 fields), HabitModel (27), ProjectModel (25), PomodoroModel, HabitCheckInModel, TaskDetailItemModel (checklist items) and FilterModel. SheetTick keeps the same concepts and drops the team and sharing fields.

REA investigation · TickTick for Android

What's inside the Android app

I ran REA's JADX provider (jadx-headless-mcp 0.7.1, on JDK 21) on base.apk, pulled from the APKMirror bundle you downloaded: com.ticktick.task 8.2.2.0 (build 8220, 26 Sep 2026), min Android 8.0, target SDK 37. I used inspect-android-package for the manifest, search-android-classes for the class inventory, and inspect-android-class on eight entity classes. Unlike the Windows build, this is the current release, so it also covers the post-2021 features. TickTick's own download link turned out to serve GNotes (org.dayup.gnotes 1.8.4.5), an old notes app from the same company, so I didn't use it.

Size of the app

  • 23,285 classes, 6,450 of them TickTick's own
  • 253 activities, 55 services, 53 receivers
  • 27 home-screen widget types
  • 2 Quick Settings tiles (quick add, voice add)
  • Kotlin with classic Android Views, greenDAO over SQLite, heavily obfuscated

Widgets (27 providers)

  • Tasks: list 4×4, scrollable, undone count, quick add, completion
  • Calendar: today, 3-day, week, grid, grid-week
  • Habits: single, week, month, progress 2×2 and 4×2
  • Focus: Pomodoro, single timer, daily focus, focus distribution (3 sizes)
  • Other: Eisenhower matrix, countdown list, single countdown, class timetable

Android-only capture

  • Quick Ball: floating add button over other apps (QuickBallService, overlay permission)
  • Share target for text, images and multiple files (ShareReceiveActivity)
  • "Add to TickTick" in any app's text-selection menu (PROCESS_TEXT)
  • Voice notes with recorder service and AI transcription (ai.audio_parse)
  • Document scanner for attachments (ML Kit)

Reminders, focus, devices

  • Exact alarms plus full-screen, alarm-style reminders; "annoying alert" = constant reminder
  • Location reminders via geofences: latitude, longitude, radius, enter or exit
  • Floating focus timer window, full-screen timer, flip-phone-to-focus
  • Watches: Wear OS plus Huawei, Honor, Xiaomi and Vivo helpers
  • AI assistant runs in a WebView with a JavaScript bridge (115 classes)

The Android entities match the Windows ones field for field (Task2 ↔ TaskModel, same etag/syncStatus sync columns), which confirms one shared server data model. Newer entities fill in the gaps in the Sheet layout: Countdown (4 types: countdown, anniversary, birthday, holiday; count-up mode; lunar calendar; 8 card styles), Timer (named Pomodoro or stopwatch timers linked to a task or habit), Location (geofence reminders), and Habit with currentStreak, maxStreak and skipped dates.

Why Flutter

  • One Dart codebase builds a native Windows app and an Android app
  • Mature packages for local notifications on both platforms, Android home-screen widgets, Windows tray and global hotkeys, and SQLite (drift)
  • Considered: Compose Multiplatform (what TickTick uses for shared logic, but its desktop target runs on the JVM), Tauri 2 (Android support is younger), .NET MAUI (smaller ecosystem)

Why local-first

  • The app reads and writes SQLite, so it's instant and works offline
  • The Sheet is the shared source of truth, not a live database
  • Same pattern REA found in TickTick: dirty flags, batch commit, pull from a checkpoint
  • Reminders are scheduled on each device, so no server is needed

Google access

  • Your own Google Cloud project with the Sheets and Drive APIs enabled
  • OAuth scope drive.file: the app sees only the Sheet and folder it created, and the scope is non-sensitive, so no Google review
  • Android uses Google Sign-In. Windows uses the desktop loopback OAuth flow
  • Apps Script is optional, for background jobs only. You already deploy with clasp
Database

The Google Sheet layout

One spreadsheet with one tab per entity. Row 1 holds column names, and every row has id (UUID), updated_at, version, device and deleted. Rows are never physically deleted during normal use. A separate read-only View tab uses QUERY() formulas to give you a clean, sorted overview without touching the raw tabs.

Sync engine

One sync cycle

A sync runs when the app opens or regains focus, 3 seconds after an edit, every 2 minutes while open, and every 15 minutes in the background on Android. A normal cycle makes 2 to 4 API requests, well under the Sheets limit of 60 requests per user per minute.

  1. Check for changes. Ask the Drive API for the Sheet's modifiedTime. If it hasn't changed since the last pull and nothing local is dirty, stop.
  2. Pull. Fetch all tabs with one values.batchGet request. For each row, compare it with the local copy. A higher version wins. If the version is the same but the row's content hash changed, you edited it by hand in Sheets, and SheetTick accepts that edit.
  3. Resolve conflicts. If a row changed on both sides, fields that differ on only one side are merged. Fields changed on both sides go to the most recent updated_at.
  4. Push. Write updated rows with one values.batchUpdate (by cached row number, checked against id). Add new rows with one append per tab. Clear the dirty flags and save the new row numbers.
  5. Reschedule reminders for anything that changed, so both devices stay in step.

Rule for manual edits in the Sheet: edit cell values freely, but don't sort, insert or delete rows in the raw tabs. Use the View tab for sorting. Compaction (actually deleting old tombstones) runs as a nightly Apps Script job under a lock. It bumps meta.compaction_epoch, which tells clients to rebuild their row-number cache.

Risks

What could go wrong

RiskMitigation
Google OAuth apps in "Testing" status issue refresh tokens that expire after 7 days, which forces a weekly sign-inIf lmathieu.com is a Google Workspace domain, set the consent screen to Internal. Otherwise publish it to Production. With only the non-sensitive drive.file scope, Google doesn't require verification.
Manual sorting or row deletion in the Sheet breaks row-number lookupsEvery write checks id before writing and falls back to a full re-index when it doesn't match. A warning row and the View tab steer you away from editing the raw tabs' structure.
Both devices edit the same task while offlineField-level merge, then most recent edit wins per field. An automated conflict test from P0 onward.
Android delays background work and alarmsExact-alarm permission for reminders (a user grant on Android 14+), WorkManager for sync, and a prompt to exempt the app from battery optimization.
Windows reminders stop when the app is closedThe app minimizes to the tray and starts with Windows. Optionally, Apps Script emails or pushes critical reminders.
Sheets API quota (60 requests per minute per user)Batched requests, the cheap Drive change check, and exponential backoff on HTTP 429.
